# DH Climate Explorer · собственные имена · 0.2.7

## Принцип

DH Climate не должен принуждать инженера переименовывать сущности в Home Assistant
ради русского отображения дерева. Explorer показывает пользовательские
подписи DH Climate. Названия HA и конфигурации видны в карточке и
форме редактирования **для справки**, но не управляют системой.

Приоритет для текущего языка: имя DH Climate → friendly_name HA →
исходное имя config → ID. Для другого языка выбирается аналогичная
независимая подпись. Пустое поле снимает пользовательское переопределение.

Ключи остаются стабильными: room:livingroom, entity:sensor.th_livingroom_temperature,
entity:climate.termostat_livingroom, resource:boiler.
Формат файла /data/dh_climate_ui_labels.json:

    {"schema_version":1,"revision":1,"labels":{
      "room:livingroom":{"ru":"Гостиная"},
      "entity:climate.termostat_livingroom":{"ru":"Термостат гостиной"}
    }}

Имена можно изменить правым кликом по комнате, сенсору, устройству,
ресурсу и насосам/контурам: «Изменить имя». Отдельная форма содержит
имена ru/en и неизменяемую информацию HA / технический ID.

## Почему файл отдельно от манифеста

UI-имена не относятся к электрическим и климатическим связям.
Их изменение должно отражаться немедленно без перезапуска регуляторов,
без Draft/Apply и без удаления состояния климатической автоматики.
Файл является SoT **только для отображаемых имён**, не для климата.
Он входит в /data штатного backup HAOS App.

## Безопасность

GET /api/labels — только через доверенный HAOS Ingress peer.
POST /api/labels — тот же peer, подтверждённые User ID + system-admin,
X-Requested-With, application/json, ограничение размера JSON.
Каждая запись атомарна; конфликт revision возвращает HTTP 409.

Миграции YAML, SQLite и MQTT не требуется; обычный пользователь может
просматривать подписи, но не редактировать их. Технические имена FAST_HEAT,
SLOW_HEAT, VIRTUAL, HARDWARE не переводятся и не переименовываются.

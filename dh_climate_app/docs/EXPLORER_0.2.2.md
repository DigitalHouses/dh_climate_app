# DH Climate Explorer · v0.2.2

## Решение

Единое дерево слева, центральная карточка выбранного объекта, Inspector
по запросу. Старые разделы «Operations» и «Configuration» не разделяют
навигацию: в будущем права будут определять доступные действия в
**том же** Explorer.

## Что действительно реализовано сейчас

- **SYSTEM → WEATHER / HOME → RESOURCES / SEASON / ROOMS**.
- В ROOMS: каждая сконфигурированная комната, Room Thermostat,
  её реальные датчики (температуры, влажности, окна), исполнительные
  устройства; численность и типы определяются конфигурацией.
- В RESOURCES: известный источник отопления (BOILER либо
  CENTRAL_HEATING), VRF при настройке, ресурсная телеметрия,
  насосы и контуры *только если они есть в конфиге*.
- Клик на имя узла открывает его содержимое. Отдельная стрелка
  раскрывает/сворачивает ветку без изменения выбранного объекта.
  Breadcrumbs позволяют перейти к предкам.
- Спальня открывается целиком: температура, уставка, профиль,
  HVAC action, состояние окна, датчики, устройства, Problems.
- Inspector можно открывать/скрывать; дерево можно скрывать и
  менять его ширину. Мобильный вариант — выдвижная левая панель.
- Статусы и температура только из existing authoritative Runtime.
  Физическое положение клапана и реальный поток воды не выводятся
  из switch.state. Неизвестное не заменяется на OFF.
- Словари ru/en расширяемы; FAST_HEAT, FAST_COOL,
  FAST_HEAT_COOL, SLOW_HEAT, VIRTUAL, HARDWARE **не переводятся**.

## Что не сделано и не имитируется

- Кнопки «+» и редактирования **нет**. Никто, включая администратора,
  не может выполнять изменения конфигурации через этот выпуск.
  Контракт HTTP остаётся только GET; App панели пока admin-only.
- Нет server-side CRUD, Draft/Validate/Apply, версии и миграции
  persisted manifest /data. Текущий SoT: Supervisor options и SQLite.
- Нет автоматической привязки HA Area, паспортов физических активов,
  каналов Dingtian, графа связей оборудования или физической диагностики.

Когда будет готов backend с настоящими правами пользователя HA и
транзакционным Apply, кнопки редактирования появятся в **этом же**
дереве, без нового режима.

## Регрессия и приёмка

Проверки в ветке:
- Python: 243 unittest, включая действующие safety / MQTT / runtime.
- Node: 7 тестов дерева (пути, ресурсы, room, датчики, устройство,
  непереводимые технические коды), JS syntax.
- CI дополнен Node-тестами перед Docker build.

Перед установкой: обновление через штатный HAOS App Store с 0.2.1,
желательно резервная копия App. Никаких изменений YAML не требуется.

Отдельная HAOS-проверка после установки:
1. Explorer раскрывается, показывает 7 комнат из домашней конфигурации.
2. Выбор комнаты открывает всю комнату; стрелка ветви только раскрывает.
3. Выбор climate.bedroom_ac показывает FAST_HEAT_COOL и тип устройства.
4. Inspector скрывается и раскрывается; работает кнопка Copy entity.
5. Доступны ресурс и его контуры, только если реально настроены.
6. SSE-обновления и offline не показывают устаревшие значения как живые.
7. Нет управляющих кнопок, команд к actuator или изменений SQLite.

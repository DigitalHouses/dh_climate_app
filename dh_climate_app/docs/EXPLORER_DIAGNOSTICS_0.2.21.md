# DH Climate App · Сохранение диагностики · v0.2.21

## Как пользоваться

В верхней панели Explorer расположена кнопка **«Сохранить диагностику»**.
Откройте проблемную страницу (например, «Погода → Приоритеты сенсоров»)
и нажмите кнопку. Браузер сформирует файл
`dh-climate-diagnostics-YYYY-MM-DDTHH-MM-SS-sssZ.json`.
При диагностике сбоя передайте этот JSON-файл вместо скриншотов.

Кнопка присутствует и в режиме только чтения. Полные внутренние
данные выдаются через `GET /api/diagnostics` **только администратору
Home Assistant**, прошедшему авторизацию Ingress. При недоступности
административного API экспорт всё равно создаётся с данными браузера
и доступным `/api/snapshot`; в файле явно отмечается частичный режим.

## Состав одного файла

### Браузер и интерфейс

- дата и время сбора, язык, размеры окна, масштаб экрана;
- текущий узел и путь дерева, все узлы дерева, раскрытые ветки;
- ширина Explorer, состояние Inspector и соединения SSE;
- весь доступный в браузере runtime snapshot и погодный каталог;
- состояние редактора, включая локальный ещё не сохранённый кандидат;
- отрисованный HTML дерева, Breadcrumbs, рабочей области, Inspector,
  контекстного меню и верхней панели (без значений секретных полей);
- актуальные значения видимых полей, CSS-правила и геометрия элементов;
- ошибки JavaScript / необработанные Promise после открытия страницы.

### Внутренние данные приложения

- точная оперативная проекция (/api/snapshot) и её revision;
- серверный манифест: конфигурация, ревизия черновика, dirty,
  pending_restart (с маскировкой учётных данных);
- пользовательские подписи объектов, связи с HA Areas;
- каталог HA: реальные имена, entity_id, текущие состояния и измерения,
  включая маппинг производных сенсоров по MQTT unique_id;
- подтверждённые факты runtime: количество отслеживаемых объектов,
  текущий кэш HA, MQTT/очередь команд, число отложенных проверок,
  признаки работы расчёта, выбранные погодные источники;
- текущие tuning-параметры из SQLite, размеры и временной диапазон
  отсчётов температуры/влажности;
- до 120 последних warning/error записей из логгеров DH Climate,
  собранных **с момента запуска текущего процесса**.

### Безопасность и ограничения

- При сборе нет Apply, restart, управляющих команд, новых MQTT-топиков,
  фоновых циклов или запросов к посторонним сервисам.
- Доступ к полному API: только HA system-admin через Supervisor Ingress.
- Токены, пароли, Authorization, cookie, author_id и ключи API
  рекурсивно маскируются перед выгрузкой. URL страницы (включая токен
  Ingress) не записывается.
- Отчёт **содержит частные названия комнат, реальные HA entity_id,
  состояния устройств, конфигурацию и детали сети**. Не публикуйте
  его без просмотра. Автоматического отправления куда-либо нет.
- Экспорт не включает системный журнал Supervisor/HA Core, всю историю
  Recorder, секреты контейнера или бинарный скриншот.
- Сбор HA Entity Catalog выполняется однократно по нажатию кнопки,
  используя текущий ограниченный allowlist и стандартный кэш API.
  Ошибка каталога отмечается в `backend.data.errors.entity_catalog`,
  остальные разделы при этом сохраняются.
- JSON является **диагностическим снимком**, не резервной копией
  манифеста и не средством восстановления.

## Приёмка

1. На проблемном экране нажать «Сохранить диагностику».
2. Убедиться, что браузер сохранил один JSON и он содержит
   `format=dh_climate_app_support_diagnostics`, `ui`, `backend`.
3. Проверить `ui.state.selection`, `ui.state.tree`,
   `ui.rendered_html["#content"]`, `ui.layout`.
4. В HA под системным администратором проверить `backend.data`:
   `manifest`, `snapshot`, `entity_catalog`, `runtime`,
   `labels` и `errors`.
5. При потере связи убедиться, что файл всё ещё создаётся,
   а `backend.ok=false`, без выдуманных оперативных данных.
6. Проверить отсутствие паролей и Supervisor token, а также отсутствие
   Apply, restart и изменения настроек после экспорта.

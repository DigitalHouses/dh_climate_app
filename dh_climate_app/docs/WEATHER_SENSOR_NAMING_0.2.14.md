# DH Climate · Погодные сенсоры, поиск и имена · 0.2.14

## Что исправлено

### 1. Выбор погодных провайдеров

Погодные провайдеры выбираются **по домену HA `weather.*`**,
а не по названию интеграции. Например, Met.no формирует
`weather.forecast_home_assistant`, а её platform ID — `met`.
Поэтому фильтрация интеграций по наличию подстроки `weather`
ошибочно скрывает Met.no и другие интеграции с собственными именами.

В Picker «Провайдеры» показываются все подходящие `weather.*`,
дополнительный выпадающий список интеграций скрыт.
В Picker отдельных `sensor.*` поиск по HA integration/platform
остаётся доступным, но они не являются списком погодных провайдеров.

### 2. Понятные entity_id производных сенсоров

Новый MQTT Discovery `default_entity_id` для **впервые создаваемых**
производных погодных сенсоров:

- `sensor.dh_climate_app_weather_p_asyl_mura_temperature`;
- `sensor.dh_climate_app_weather_p_asyl_mura_humidity`;
- `sensor.dh_climate_app_weather_p_forecast_home_assistant_temperature`.

Часть `p_asyl_mura` — пример ID, созданного из
`weather.asyl_mura` автоматическим преобразованием предыдущей
конфигурации. Фактический ID зависит от ID провайдера.

**Важно:** HA применяет `default_entity_id` только при первом
создании сущности. Если MQTT-сенсор уже зарегистрирован в HA
под именем `sensor.dh_climate_app_provider_…`, он сохранит этот
`entity_id`. Версия 0.2.14 намеренно **не меняет `unique_id`,
discovery topic и retained state topic**, чтобы не создавать
дубликаты и не нарушить прежнюю историю Recorder. При необходимости
существующий `entity_id` можно вручную переименовать в настройках
сущности Home Assistant.

### 3. Названия, видимые в HA

В Explorer → Погода → ПКМ → Настроить источники погоды:

1. В разделе «Провайдеры» выбрать `weather.asyl_mura`.
2. Ниже появится подраздел **«Названия погодных сенсоров»**.
3. По отдельности выбрать «Изменить имя» для провайдера,
   производной температуры и производной влажности.
4. Ввести, например, русское имя **«Google температура на улице»**
   для температуры, **«Google влажность на улице»** для влажности.
5. «Сохранить имя» возвращает к открытой форме погоды без потери
   незаписанных источников или приоритетов.

Имена хранятся в существующем `/data/dh_climate_ui_labels.json`,
**не являются частью климатического манифеста** и не меняют ID.
Для уже действующего провайдера они повторно публикуются в MQTT
Discovery сразу, для ещё не применённого источника — после
сохранения Draft → Validate → Apply → отдельный перезапуск App.
Само сохранение имени не включает провайдер.

Home Assistant формирует отображаемое имя MQTT-сущности с учётом
имени устройства и имени его показателя; поэтому итоговое
`friendly_name` может содержать префикс названия устройства.
Если пользователь явно переименовал сущность в самом HA, его
переопределение может иметь приоритет над именем из MQTT Discovery.

**Внешние сущности `sensor.*`**, созданные другой интеграцией,
не переименовываются DH Climate в HA: у них уже есть собственный
владелец и устойчивая HA identity. Для них название в HA
редактируется в Настройки → Устройства и службы → Сущности.
Это ограничение предотвращает вмешательство в сторонние интеграции.

## Проверки

- Met.no `weather.forecast_home_assistant` виден среди погодных
  провайдеров, даже если platform ID называется `met`.
- Поиск `weather` в Picker провайдеров находит его по entity_id.
- После выбора Google доступны отдельные команды переименования
  провайдера, температуры и влажности.
- Сохранение имени возвращает в редактор погоды и не теряет
  изменения ещё не сохранённого черновика.
- У новых MQTT-сенсоров в `default_entity_id` есть `weather`;
  `unique_id` и MQTT state topics совпадают с 0.2.12/0.2.13.
- У существующих HA-сенсоров не происходит автоматического
  изменения entity_id или обнуления истории.
- Обновление версии само по себе не меняет активные приоритеты
  и не выполняет Apply.

# DH Climate Explorer · Редактор конфигурации 0.2.3

## Архитектура и права

Один Explorer для всех пользователей. Разделения на Operations / Configuration нет.
Иерархия и оперативные данные остаются прежними.

- Авторизованный пользователь HA: наблюдение в Ingress.
- Подтверждённый администратор (группа system-admin, заголовки Supervisor):
  создание, изменение, удаление комнат и устройств, редактирование списков
  комнатных датчиков. Проверка прав **на сервере каждого запроса**.
- UI не выдаёт пароль и не хранит собственных пользователей.
- TCP-запросы только от Supervisor 172.30.32.2. POST требует JSON,
  X-Requested-With: DHClimateExplorer, верхний предел 256 KiB.
- Если Supervisor не передал User ID или Groups, редактирование недоступно.
- Добавление pumps/circuits, редактирование ресурсов / outdoor / глобальных
  настроек через визуальные формы пока не реализовано.

## Источник истины и обновление

Изначально, до первого Apply, источник — штатный /data/options.json,
который управляется Supervisor. Первый открытый редактор читает именно
его текущий валидный формат 0.2.0.

После первого Apply:
- /data/dh_climate_manifest.json — каноническая структура конфигурации
  при **следующем запуске приложения**.
- /data/dh_climate_manifest.draft.json — черновик, не влияет на Runtime.
- /data/dh_climate_manifest.previous.json — предыдущая опубликованная
  конфигурация (для первого Apply — снимок Supervisor options).
- SQLite (/data/dh_climate.db) по-прежнему хранит уставки и оперативные
  настройки; не копируется и не изменяется редактором.
- Сам /data/options.json не редактируется и не удаляется. После Apply
  форма Supervisor может показывать прежние параметры: **не используйте**
  её для правки канонической структуры, пока существует манифест.

## Создание новой комнаты

1. В Explorer развернуть HOME → ROOMS.
2. Нажать + у ROOMS (доступен только администратору).
3. Ввести уникальный id в snake_case, отображаемое имя,
   хотя бы один sensor.* температуры, опционально датчики влажности/окон.
4. Нажать «Сохранить черновик». Комната помечается «ЧЕРНОВИК»,
   значения Engine для неё ещё неизвестны.
5. Нажать «Проверить» (действующий parse_options). При ошибке
   исправить форму и сохранить новый revision.
6. После штатного backup нажать «Применить» и ввести APPLY.
7. Приложение **не перезапускается автоматически**; пользователь
   перезапускает DH Climate App в HAOS осознанно.
   После успешного запуска отображается конфигурация нового манифеста.

## Редактирование и удаление

Открыть комнату или устройство, нажать «Редактировать».
Изменять только поддерживаемые поля. Для fast_heat_cool
использовать role=fast_heat и reversible=true: это строго действующий
контракт движка, а отображаемое имя FAST_HEAT_COOL не переводится.

Удаление комнаты или устройства требует отдельного подтверждения;
до Apply и перезапуска команда удаления не влияет на оборудование.
После изменения нажать Save → Validate → Apply. При конфликте ревизий
первый редактор получает 409, а не перезаписывает чужой черновик.

## Поведение при сбоях / откат

- Неудачная валидация не создаёт активный манифест.
- Выход из редактора до «Сохранить» отменяет несохранённую форму.
- «Сбросить черновик» удаляет только draft, не активную конфигурацию.
- Применённый манифест записывается атомарно и активируется при рестарте.
- При повреждённом активном манифесте приложение не запускает
  Engine с неожиданной альтернативной конфигурацией. Требуется
  восстановить App из штатного backup либо восстановить
  /data/dh_climate_manifest.previous.json в качестве активного
  манифеста из окружения, которое имеет доступ к данным именно этого App.
  HA Terminal обычно не имеет прямого доступа к /data другого App.
- После отката необходимо перезапустить приложение.

## Acceptance на домашнем HAOS

1. Сделать backup DH Climate App, включая /data.
2. Обновить 0.2.2 → 0.2.3; проверить 7 комнат и актуальные уставки.
3. Под администратором убедиться в наличии + и «Редактировать».
4. Добавить демонстрационную комнату только в **черновик**, проверить
   что Engine и существующие MQTT entities не изменились.
5. Применять только после полной проверки и с отдельным разрешением
   на изменение живой конфигурации; рестарт — отдельный шаг.
6. Под обычным пользователем проверить, что Explorer читает данные,
   но POST/config недоступны.

## Что завершено

Новый Climate App спроектирован и реализован как компактное приложение Home Assistant. Старый PostgreSQL Climate 5 используется только как **источник контракта поведения**.

Архитектура PostgreSQL намеренно не переносилась.

Из новой схемы удалены:

- PostgreSQL как business engine;
- SQL jobs и handlers;
- подсистема Matrix;
- подсистема Firewall;
- Dispatcher;
- UC queue;
- lifecycle Universal Controller;
- lifecycle Confirmator;
- PostgreSQL runtime/session machinery.

Новая архитектура:

```text
Состояния Home Assistant
        ↓
Python Climate Core
 ├─ Outdoor / avg24 / season
 ├─ Room thermostat
 ├─ Humidity
 ├─ FAST/SLOW policy
 └─ Safety predicates
        ↓
Желаемое физическое состояние
        ↓
Сервисы Home Assistant

Climate Core
        ↓
MQTT Discovery
        ↓
Home Assistant UI
```

## Реализованное продуктовое поведение

### Outdoor / season

- упорядоченные priority/fallback источники наружной температуры;
- упорядоченные priority/fallback источники наружной влажности;
- приоритеты температуры и влажности независимы;
- rolling avg24 наружной температуры;
- rolling history сохраняется в SQLite;
- потеря live outdoor temperature принудительно переводит season в OFF;
- глобальные состояния сезона:
  - `heat`
  - `cool`
  - `off`;
- формула season сохраняет семантику thresholds/hysteresis Climate 5;
- по текущему продуктовому решению используется один глобальный гистерезис температуры дома;
- MQTT `heat_cool` facade с двумя порогами:
  - low target = порог отопительного сезона;
  - high target = порог сезона охлаждения;
  - current temperature = avg24;
  - action = heating/cooling/idle;
- изменения thresholds переживают restart.

### Комнаты

- одна настроенная комната = один MQTT Device;
- поэтому каждую комнату можно назначить соответствующей Home Assistant Area;
- одна основная `climate` entity на комнату;
- room temperature = среднее текущих валидных настроенных room temperature sensors;
- room humidity = среднее текущих валидных humidity sensors;
- профили:
  - day
  - night
  - away
  - antifreeze;
- приоритет профилей сохранён из legacy Climate 5;
- room target matrix сохраняется по room × season × profile;
- временный profile-edit overlay сохранён из legacy facade;
- room HVAC mode ограничен глобальным season;
- stateful симметричный hysteresis;
- previous action сохраняется, поэтому restart не сбрасывает состояние hysteresis.

### FAST devices

Поддерживаемые физические domains:

- `switch`;
- `climate`.

FAST devices следуют demand комнатного термостата.

Для `climate` actuators App задаёт HVAC mode и room target.

Для `switch` actuators App задаёт on/off.

Execution идемпотентен: команды отправляются только если desired state отличается от actual HA state.

### SLOW devices

Первая реализация поддерживает SLOW heating только через локальные физические `climate` thermostats.

Типичный use case: термостат пола/стяжки со своим локальным probe.

Поведение:

```text
HEAT season -> climate heat + slow_target
COOL/OFF    -> climate off
```

SLOW не циклируется по demand комнатного термостата температуры воздуха.

Физический термостат остаётся локальным финальным контуром управления/безопасности.

Простой SLOW switch в v0.1 запрещён, потому что непрерывный сезонный ON нельзя считать безопасным универсально.

### Влажность

Опционально для комнаты:

- humidifier;
- dehumidifier.

Публикуется через нативный MQTT facade `humidifier`.

Включает:

- current humidity;
- сохраняемый target;
- независимый humidity hysteresis;
- прямое управление switch/humidifier actuator.

### Контекст окна

Восстановлена legacy-семантика состояния окон комнаты:

```text
any open contact            -> open
none open + one unavailable -> unknown
otherwise                   -> closed
```

Window state — контекст, а не thermostat truth.

Только устройства, явно перечисленные в `window_off_devices`, принудительно выключаются при открытом настроенном окне комнаты.

Unknown для настроенного окна публикуется как warning Problem.

### Защита reversible climate при низкой наружной температуре

В legacy Climate 5 был `ac_min_outdoor_temperature` с default `-10 °C`.

Новый App применяет это поведение к reversible FAST `climate` entities, указанным и в heat, и в cool lists.

При heating:

```text
current outdoor temperature < ac_min_outdoor_temperature
-> reversible climate device held OFF
```

Остальные допустимые heating devices остаются независимыми.

## Persistence

Путь SQLite:

```text
/data/dh_climate.db
```

Хранится только состояние, которое должно пережить restart:

- season thresholds;
- rolling outdoor samples;
- room target matrix;
- room climate control state;
- previous room thermostat action;
- humidity targets/control state.

SQLite не используется как orchestration engine.

## Подключение к HA

Реализовано:

- Supervisor REST API;
- HA WebSocket state subscription;
- reconnect по subscribe-before-snapshot;
- state cache с защитой timestamp;
- старые buffered events не могут перезаписать более новый snapshot truth;
- cached HA truth отбрасывается при disconnect;
- физические команды не отправляются без live HA connection.

## MQTT / диагностика

Реализовано:

- системный MQTT Device;
- один MQTT Device на комнату;
- season climate facade;
- room climate facades;
- опциональные humidity facades;
- retained discovery/state;
- retained MQTT commands игнорируются;
- диагностика Version;
- диагностика Started at;
- агрегированная диагностика Problem.

## Reconciliation устройств

Реализовано:

- desired-state compiler;
- сравнение desired-vs-actual;
- прямое выполнение HA service;
- bounded retry;
- cooldown после failed confirmation;
- диагностика unavailable entity;
- capability/range protection.

## Telemetry

Реализована поддержка DigitalHouses Telemetry Protocol v1.

Свойства на тот момент:

- default disabled;
- постоянные anonymous installation UUID/token;
- daily heartbeat с deterministic jitter;
- heartbeat eligibility при смене версии;
- one-hour failure backoff;
- ошибки telemetry не влияют на climate runtime;
- authenticated installation deletion;
- payload не содержит room/entity/device/climate data.

Telemetry product identity:

```text
digitalhouses_climate_app
```

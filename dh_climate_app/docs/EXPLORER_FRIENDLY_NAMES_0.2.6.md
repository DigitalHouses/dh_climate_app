# DH Climate Explorer · отображаемые имена · 0.2.6

## Цель

Одно дерево должно быть понятным инженеру и заказчику на выбранном
языке без изменения технических идентификаторов, MQTT или конфигурации
регуляторов.

## Приоритеты отображения

- Системные узлы SYSTEM / HOME / WEATHER / RESOURCES / SEASON / ROOMS:
  словарь ru/en интерфейса (на русском: Система, Дом, Погода,
  Ресурсы, Сезон, Комнаты).
- Ресурсы: словарь ru/en для известных типов. Например,
  boiler → Котёл, central_heating → Центральное отопление.
- Комнаты: friendly_name сущности climate.dh_climate_app_<room.id>,
  если она присутствует в текущем HA state и имеет непустой атрибут.
  Иначе — room.name из конфигурации, далее технический room.id.
- Датчики и устройства: friendly_name из текущего HA state,
  иначе — неизменённый entity_id.
- Насосы и контуры, не имеющие отдельной HA-сущности, сохраняют
  заданные в конфигурации name.
- Технические классы FAST_HEAT, FAST_COOL, FAST_HEAT_COOL,
  SLOW_HEAT, VIRTUAL, HARDWARE — не переводятся.

HA friendly_name — это имя для отображения; оно не является привязкой
к комнате. HA Area также не используется как обязательная связь.

## Настройка на действующем HAOS

Если в дереве по-прежнему показано Living Room, значит у
climate.dh_climate_app_livingroom нет пригодного русского friendly_name.
Можно задать в Home Assistant отображаемое имя «Гостиная»
для этой сущности. После получения обновлённого HA state Explorer
отобразит имя без изменения room.id= livingroom.

Точно так же sensor.th_livingroom_temperature можно назвать
«Температура гостиной», а climate.termostat_livingroom —
«Термостат гостиной».

Для проверки правильного объекта предусмотрены подсказка при
наведении, Inspector и неизменённый entity_id в карточке.

## Безопасность и ограничения

- В Ingress передаётся только отдельно выбранная строка
  friendly_name (до 160 символов), а не все HA attributes.
- Отсутствие friendly_name не вызывает перевод имени по догадке,
  блокировку дерева или изменение идентичности узлов.
- Это не многоязычное хранилище room labels — пользовательские
  псевдонимы из HA могут быть на любом языке независимо от
  выбранного языка интерфейса.
- UI не переписывает Home Assistant friendly_name: переименование
  осуществляется средствами Home Assistant.
- Ни одна операция над климатом не зависит от имён в UI.

## Приёмка

1. После обновления Ingress разделы Система / Дом / Комнаты — на русском.
2. Переименовать произвольный тестовый датчик через штатный HA UI.
3. Проверить, что новое friendly_name видно в дереве и карточке,
   но при этом entity_id не изменился.
4. Переименовать комнатную climate-сущность и проверить имя комнаты.
5. При отсутствующем friendly_name должен остаться исходный ID
   либо каноническое имя комнаты, без ошибок и потери объекта.

# DH Climate Explorer · DH Room ↔ HA Area · 0.2.10

## Принцип

**DH Room** — объект климатического управления. **HA Area** — справочная классификация Home Assistant для поиска и интерфейса. Связь между ними необязательна, не создаёт HA Area и не влияет на климатический алгоритм.

## Управление связью

В Explorer выбрать комнату → ПКМ → «Редактировать комнату». Под названием комнаты располагается поле «HA Area — связь только для навигации».

В списке доступны реальные HA Area и вариант «Без связи с HA Area». Нажатие **«Сохранить HA Area»** записывает *только UI-метаданные*: не сохраняет черновик климатической конфигурации, не требует Validate/Apply и не перезапускает Engine. Для новой комнаты сначала сохранить её в черновике, чтобы room.id стал определённым.

В карточке комнаты в блоке «Идентификация» отражается связанная HA Area. Существующие значения температурных уставок и связи с исполнительными устройствами остаются неизменными.

## Entity Picker

Если для комнаты назначен area_id из реестра HA, Picker при открытии автоматически выбирает именно эту зону. Инженер всегда может переключить фильтр на «Все зоны», «Без зоны» или любую другую HA Area.

Если явной связи нет, Picker может предложить зону по точному совпадению текущего имени комнаты DH с названием HA Area, иначе начинает со «Все зоны». Это подсказка, а не обязательное соответствие.

Если назначенная HA Area удалена из Home Assistant, её ID остаётся в UI-метаданных. Редактор помечает потерянную связь и предлагает выбрать новую или снять старую. Picker начинает со «Все зоны», предупреждая о потерянной связи. Автоматически заменять area_id по имени нельзя.

## Хранение и совместимость

Используется существующий файл `/data/dh_climate_ui_labels.json` — без новой БД:

```json
{
  "schema_version": 1,
  "revision": 4,
  "labels": {
    "room:livingroom": {"ru": "Гостиная"}
  },
  "room_areas": {
    "livingroom": "gostinaya"
  }
}
```

Старые версии файла без поля room_areas корректно загружаются с пустым сопоставлением. Записи UI-имён и сопоставлений HA Area используют общий revision с блокировкой конкурентных записей и атомарное сохранение. Данные входят в обычную резервную копию App.

GET /api/labels возвращает room_areas вместе с labels (через защищённый HAOS Ingress). POST /api/room-area принимает room_id, area_id (строка либо null) и revision, только для system-admin, с проверкой Supervisor peer, CSRF-маркера и JSON. Отказ при устаревшей ревизии — HTTP 409.

**Не изменяются:** конфигурационный манифест, Supervisor options, Home Assistant Area Registry, MQTT, SQLite, устройство Climate Engine, любые значения уставок и правила регулирования.

## Приёмочный тест дома

1. Убедиться, что App обновлён, существующая конфигурация не изменена.
2. В Explorer открыть «Редактировать комнату» для Living Room.
3. Выбрать из списка HA Area «Гостиная» и нажать «Сохранить HA Area».
4. Открыть Picker температуры — выбранная зона должна быть «Гостиная».
5. Переключить на «Все зоны»: появятся датчики других зон.
6. Отменить редактирование комнаты, обновить браузер и снова открыть Picker.
7. Убедиться в сохранении зоны, неизменности привязанных датчиков и уставок.
8. По возможности проверить удалённую HA Area: предупреждение + «Все зоны» без скрытого переназначения.

Это UI-сопоставление, **Apply и перезапуск App не требуются**.

# DH Climate App · отдельный тест редактора Supervisor

**Временный стенд исключительно для проверки UI.** Не является климатическим контроллером. Его slug — `dh_climate_schema_probe`, отличный от рабочего `dh_climate_app`.

## Состав и границы

- `config.yaml` содержит **ту же секцию `schema:`**, что кандидат `dh_climate_app/config.yaml`.
- Пример `options` состоит только из фиктивных `sensor.probe_*`, `climate.probe_ac` и `switch.probe_floor`.
- Нет `homeassistant_api`, `hassio_api`, MQTT service dependencies, команд управления или скриптов HA.
- `boot: manual`; запускать этот App для редактирования настроек не требуется. Dockerfile лишь позволяет Supervisor выполнить установку.
- Каталог существует **только в тестовой ветке** `test/0.1.32-rc1` и не предназначен для переноса в основную ветку/release.

## Порядок GUI smoke на изолированном HAOS

1. Использовать локальную тестовую копию каталога `dh_climate_schema_probe` (не заменять содержимое уже установленного рабочего App).
2. Открыть настройки тестового App в Supervisor; в списке комнат открыть «Тест комнаты».
3. Проверить отображение двух `temperature_sensors`, добавление третьего и удаление первого; сохранить, выйти из редактора и снова открыть, проверить порядок.
4. Проверить вложенные `devices`, `role`, `control`, `actuator` и `reversible`. Сохранить, закрыть и снова открыть.
5. Переставить `outdoor.temperature_sources` (приоритетные значения), сохранить и открыть снова.
6. Проверить несколько комнат, пустые списки, русские надписи, ошибку для невалидной роли.
7. Зафиксировать версии HAOS/Supervisor, screenshot GUI и сохранённые test options.
8. Отдельно протестировать обновление **тестового** App со старой несовместимой schema и только потом согласовать порядок перехода рабочего приложения.

Ни один шаг не должен обращаться к существующему `8d59ce70_dh_climate_app`, его SQLite или реальным HVAC.
